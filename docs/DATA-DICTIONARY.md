# 数据字典

| 字段 | 含义 | 约束 |
|---|---|---|
| `datasets[].id`, `revision` | 数据集和变换修订 | ASCII 字母、数字、下划线和短横，保留前导零；每数据集至多 12 条输入边。 |
| `datasets[].inputs[].dataset`, `lag` | 上游名与读取时差 | 当下游日为 D 时读取 `D−lag`；天数 0–7。依赖图须无环。 |
| `heads[].dataset`, `day`, `version`, `rows` | 当前分区指针及行数 | 分区由 `dataset@YYYY-MM-DD` 标识。当前快照每分区唯一。 |
| `changes[].version`, `previous`, `rows` | 源分区的新版本、预计当前版本、行数 | `previous=null` 代表期望新增。仅源表可登记直接变更。兼容旧 `count` 字段。 |
| `through` | 分区截止日 | 包含该日期，从最早受影响输入向下游传播，不触及截止之后的分区。每条变更回溯最多 31 日。 |

相同变更的重传计为重复。相同分区的候选版本或行数打架时全部隔离，保留行号。每个分区先计算最终应读哪些快照，按数据集拓扑序再按分区日排列。已阻断的计划不会被依赖者误当作有效输入，窗口内未受影响的依赖可复用当前快照。

新版本由下游数据集、规则修订、分区日和排序后的输入版本及行数共同计算 SHA-256。演示数据集执行拼接，各读入分区行数相加。数值使用整数，超出 JSON 常见安全整数范围的汇总或派生数按字符串输出。

写入演练先核验每个待写指针，再一次性生成新视图。回滚先核验仍持有演练发布版本，再逐项恢复原指针，新增分区则移除。任一指针陈旧时整组拒绝。该过程作用于清单中的副本，实际仓库的调度与执行另由值班系统负责。

受影响分区 = 待写 + 复用 + 阻断。输入行数 = 采信 + 隔离 + 重复。写入后的行数 = 原行数 + 待写分区行数增量。阻断保留原快照行数。批次绑定原始字节和规则版本，文件大小至多 300 KiB。

## 下游通知

| 字段 | 含义 | 约束 |
|---|---|---|
| `owners.json` 的 `groups` | 数据集到责任组的登记 | 键为数据集标识，组名 1–40 字。文件缺失视为空登记；内容无效时拒绝生成新批次，已存批次仍可读取。 |
| `通知.批次` / `通知.计划` | 通知批次号与所属计划批次 | 每计划至多一批，由计划号、规则版本与责任依据快照共同计算。 |
| `通知.处置次序` | 组内分区的处理顺序 | 固定为停批 → 重做 → 审计：阻断先停批，待写需重做，复用可继续读取仅留审计。 |
| `通知.组通知[].分区[].来源` | 该分区的受影响来源 | 沿排程上游链回溯到采信的源分区变更。 |
| `通知.待归属[]` | 缺责任组的受影响分区 | 责任缺失的范围不得写成已通知完成：`覆盖.通知完成` 仅在待归属为零时为真，且 受影响 = 已归属 + 待归属。 |
| `通知.影响来源[]` | 采信变更的版本、上一版、行数与源行 | 从批次回查影响来源与原始清单位置。 |
| `通知.责任依据` | 生成时责任登记的快照及摘要 | 登记被误删或改动后，仍可查当时的处置范围。 |
